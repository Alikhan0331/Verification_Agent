# Вход в мобильное приложение по одноразовому коду

Учебный документ для проверки агента. Содержит намеренно заложенные дефекты.

## Общие сведения

| Поле | Значение |
| :--- | :--- |
| **Наименование задачи** | Вход по одноразовому коду из SMS |
| **Версия / дата** | 2.0 / 20.10.2026 |
| **Продукт** | Мобильный банк, аутентификация |
| **Тип работы** | Новый функционал |

## Цели
Обеспечить безопасный и удобный вход клиента в приложение без пароля.

## Функциональные требования

* **FR-1.** Пользователь вводит номер телефона, система отправляет одноразовый код.
* **FR-2.** Код состоит из 4 цифр и генерируется на сервере функцией Math.random().
* **FR-3.** Код действует достаточно долго для ввода.
* **FR-4.** После 3 неверных попыток ввода кода вход блокируется на некоторое время.
* **FR-5.** Абонент может запросить повторную отправку кода.
* **FR-6.** До 10 неверных попыток ввода кода допускается в течение суток, после чего учётная запись блокируется.
* **FR-7.** Клиент, ввёвший верный код, получает доступ к главному экрану.
* **FR-8.** Код хранится в базе данных в открытом виде для быстрой сверки.
* **FR-9.** Система отправляет код по SMS, e-mail и push-уведомлением одновременно, а при ошибке отправки повторяет попытку.

## Нефункциональные требования

* **NFR-1.** Интерфейс ввода кода должен быть интуитивно понятным.
* **NFR-2.** Код должен приходить мгновенно и гарантированно.

## Безопасность

Хранение чувствительных данных выполняется в соответствии с политикой безопасности банка: пароли и секреты хранятся только в виде хэшей.

## Критерии приёмки

| Исходные условия | Действие | Ожидаемый результат |
| :--- | :--- | :--- |
| Пользователь запросил код и ввёл верный код | Нажать «Войти» | Открыт главный экран |
| Пользователь ввёл неверный код 3 раза | Ввести верный код | Вход выполнен |
