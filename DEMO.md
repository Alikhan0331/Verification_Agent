# Демонстрация агента reqcheck (3–5 минут)

Сценарий для записи экрана или живого показа. Все команды выполняются в корне репозитория.

## 0. Подготовка (до записи)

```powershell
python -m venv .venv ; .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env      # вписать GEMINI_API_KEY (бесплатный ключ Google AI Studio)
```

## 1. Одна команда: проверка документа организаторов (≈1 мин рассказа, прогон идёт 10–20 минут)

```powershell
python -m reqcheck docs/requirements.md report.md --json report.json
```

Что показать в логе: семь шагов (нарезка → проверка требований → набор и противоречия → дубли → верификация →
уточняющие вопросы → итог), параллельные пачки, переключение моделей при перегрузке. На записи удобнее
показать готовый `report.md` из репозитория и сказать, что он получен именно этой командой.

## 2. Отчёт: что в нём (≈1,5 мин)

Открыть `report.md` и пройти по разделам:

1. Паспорт: документ, дата, модель, версия агента (коммит).
2. Нарезка: таблица «ID в отчёте — ID в документе — формулировка».
3. Проверка требований: матрица 10 критериев; у каждого дефекта дословная цитата и номер строки.
4. Проверка набора: противоречия (Ф-3 и Ф-4, граница месяца), пропуски, чек-лист ревью из документа.
5. Сводка и вердикт «НЕТ» с критичными дефектами.
6. **Раздел 7 — уточняющие вопросы автору**: вопрос, адресат, «блокирует разработку», варианты ответа, цитата-основание.
7. Итог: что исправить в первую очередь.

Подчеркнуть: каждое замечание привязано к тексту документа; цитаты, которых в документе нет, агент отбрасывает
сам (Приложение Б), а замечания, не подтверждённые проверяющим проходом, показывает отдельно (Приложение А).

## 3. Диалог с автором (≈1 мин)

```powershell
python -m reqcheck.reply template docs/requirements.md report.json answers.md
# автор вписывает ответы (пример: examples/answers_demo.md)
python -m reqcheck.reply apply docs/requirements.md report.json examples/answers_demo.md report_after.md
```

Показать в `report_after.md`: оценку каждого ответа (закрывает / частично / недостаточно / противоречит),
готовую формулировку для вставки в документ, «Приложение В» с закрытыми дефектами, пересчитанный вердикт
и встречные вопросы.

## 4. Качество и надёжность (≈30 с)

```powershell
python -m pytest -q                                        # 70 офлайн-тестов
python -m reqcheck.eval tests/corpus --results eval_out    # полнота на корпусе с заложенными дефектами
```

Сказать: корпус из 7 документов (5 с заложенными дефектами, 2 чистых контрольных без ложных срабатываний);
на документе организаторов найдены 24 из 24 заложенных дефектов, критичные 5 из 5.

## Ответы на вероятные вопросы

- **Почему не несколько независимых агентов?** Роли разделены промптами и контрактами, но всё, что можно
  посчитать кодом (нарезка по разметке, линтер, вердикт, сверка цитат), считает код: это дешевле и воспроизводимо.
- **Как защищены от выдумок?** Дословная цитата + поиск в тексте кодом + отдельный скептичный проход.
- **Что при перегрузке или лимитах бесплатного тарифа?** Ротация ключей, цепочка моделей, повторы, таймаут.
- **Что агент не умеет?** См. раздел «Что не проверено» в README.
